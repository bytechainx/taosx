# taosx 标准

**crate**：`taosx` v0.1.5 · 依赖：`reqwest`、`tokio-tungstenite`、`tokio`、`serde`、`thiserror`、`tracing`

## 1. 定位

taosx 提供 TDengine 的异步访问能力：REST 与原生 WebSocket 双传输、连接池与背压、批量写入与分块
SQL 构造、有界查询流、重试策略与指标导出。零内部耦合，不实现任何领域模型或业务编排。

## 2. 数据约定

- 时间戳以 `i64` 纳秒进入 `TaosPoint`，写 SQL 时按 `TsPrecision`（Ms/Us/Ns）换算为十进制整数，
  禁止浮点参与时间戳拼接。
- 标识符（库名 / 超级表名）必须通过白名单校验：字母或下划线开头，仅含 `[A-Za-z0-9_]`，限长。
- tag 值十六进制编码进子表名；字符串字面量按 TDengine 规则转义（`\` → `\\`、`'` → `\'`）。
- `build_insert_sql_chunks` 是 SQL 注入防护的唯一入口，新增写入路径必须复用该函数，禁止手工拼接 SQL。

## 3. 资源治理

- 所有资源上界（批量行数/字节、in-flight 并发、查询行数、响应字节、关闭超时）在
  `validate` 构建期 **fail-fast 拒绝**越界，禁止运行期无界增长或静默 clamp。
- `TaosPool::new` 只校验配置并装配 HTTP 客户端，**不发网**。`TaosPool::connect` 会发网：
  `database` 非空时经 REST 建库并探测精度，然后 `ping`；`NativeWs` 另先做 WS 握手。
  握手之后 DDL / `exec` / `query` 仍默认走 REST（WS SQL 用 `exec_sql_ws`）。
- 连接池 in-flight 以信号量背压；获取超时由 `acquire_timeout` 配置，超时返回错误而非无限等待。
- `TaosQueryStream` 是有界流：逐块拉取，单次响应受 `HARD_MAX_RESPONSE_BYTES` 约束。
- 重试仅针对瞬时错误（网络 / 超时 / 5xx），指数退避 + 抖动；鉴权与语法错误立即返回。

## 4. 安全约定

- 凭据（user / password）只能经环境变量（`FOUNDATIONX_TAOSX_*`）或 builder 注入，禁止进入 TOML 明文仓库配置。
- 错误消息与 `Debug` 输出不回显密码；日志经 `tracing` 结构化字段输出，不打印完整凭据。
- 远程端点强制 HTTPS/WSS；明文 HTTP/WS 仅允许 loopback 开发端点。

## 5. 验收

```text
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo test --all-targets
cargo package --no-verify
```

热路径基准（离线）：

```text
cargo bench --bench hot_path -- --quick
```

测试至少覆盖：标识符白名单与转义边界、分块 SQL 构造（行数/字节上限切分）、配置越界
fail-fast、错误路径类型断言、池统计一致性、重试可重试/不可重试分类。

## 6. 质量门禁约束

- crate 级 `#![forbid(unsafe_code)]`、`#![deny(missing_docs)]`、
  `#![deny(clippy::unwrap_used, clippy::expect_used, clippy::panic)]` 不得移除。
- 公共 API 变更必须同步更新 `docs/API.md` 与本文件；breaking 变更走 SemVer major + CHANGELOG。
